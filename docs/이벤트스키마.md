# 이벤트 스키마 (Kafka + Avro)

발행·구독 담당이 서로 기다리지 않도록 **이 문서가 계약**이다. 스키마 원본은 `avro/*.avsc` 3개이며
fastavro 로 직렬화 왕복 검증됐다. 변경은 PM 승인 후 전체 공유.

## 토픽

| 토픽 | 이벤트 | 발행 | 구독 | 추천 가중치 |
|---|---|---|---|---|
| `product-viewed` | PRODUCT_VIEWED | commerce-service | recommendation-service | 1 |
| `cart-added` | CART_ADDED | commerce-service | recommendation-service | 0 |
| `order-completed` | ORDER_COMPLETED | commerce-service | recommendation-service | 50 |

- 가중치 근거: 주문이 가장 확실한 선호 신호(조회 1 : 주문 50). 장바구니는 **가중치 0이지만 발행·저장은 유지**
  — 핵심 요구사항 6번이 행동 이벤트를 "조회/장바구니/구매" 3종으로 명시.
- `ORDER_COMPLETED` 는 **결제 승인(PAID) 시점**에 **주문 품목별 1건** 발행한다.
  (품목별 발행이어야 상품·카테고리 단위 가중치 계산이 단순해진다)

## 공통 필드

| 필드 | 타입 | 설명 |
|---|---|---|
| memberId | long | 회원 id |
| productId | long | 상품 id |
| category | string | 행동 시점의 상품 카테고리 (비정규화 — 구독 측이 상품 조회 없이 가중치 계산) |
| occurredAt | timestamp-millis | 발생 시각 |

추가 필드: `cart-added` → qty / `order-completed` → qty, unitPrice, orderNo, paymentMethod

## 운영값

| 항목 | 값 | 비고 |
|---|---|---|
| 파티션 | 토픽당 3 | 개발·시연 규모 기준 |
| replication factor | 1 | 단일 브로커 |
| 컨슈머 그룹 | `reco-service` | recommendation-service 인스턴스가 공유 |
| 키 | memberId | 같은 회원 이벤트의 순서 보장 |

## Schema Registry (선택 2번)

- Confluent Schema Registry :8085 (product-service 8081 과 충돌하므로 기본 8081 → 8085 변경)
- 호환성 모드 **BACKWARD** — 필드 추가 시 구버전 컨슈머가 신버전 이벤트를 읽을 수 있는지 검증
- 등록 subject: `<토픽명>-value` 3개

## 페이로드 예시

```json
// order-completed
{ "memberId": 1, "productId": 10, "category": "간식/디저트",
  "qty": 1, "unitPrice": 15000, "orderNo": "ZP1001",
  "paymentMethod": "카카오페이", "occurredAt": 1765600000000 }
```
